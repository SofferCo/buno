# תוכנית־על · מפרוטוטייפ למוצר חי

**סטאק:** Supabase (DB · Auth · Storage · Edge Functions) + Claude API + WhatsApp Business API
**עיקרון מנחה:** ערך מוקדם, סיכון נמוך. כל שלב עומד בפני עצמו ונותן משהו שאפשר להשתמש בו.

---

## תמונת הארכיטקטורה

```
   דפדפן / מובייל                Supabase                    שירותים חיצוניים
  ┌──────────────┐        ┌───────────────────┐           ┌──────────────────┐
  │ React (הקוד  │◄──────►│ Postgres + RLS     │           │ Claude API       │
  │ הקיים שלנו)  │  SDK   │ Auth (OAuth/מייל)  │           │ Gmail / GCal     │
  │              │        │ Storage (קבצים)    │◄─────────►│ Google Drive     │
  │ ChatPanel ───┼───────►│ Edge Functions:    │  OAuth    │ WhatsApp BSP     │
  └──────────────┘  HTTPS │  • /chat (assistant│           └──────────────────┘
                          │  • /sweep (cron)   │
   WhatsApp ─────────────►│  • /wa-webhook     │
                          │  • /oauth-callback │
                          └───────────────────┘
```

**מודל הליבה:** `project` = ישות משותפת. `project_member` = הרשאה פר־פרויקט (owner/member/viewer) — "האזורים החופפים". העוזר = עוד שחקן שפועל בשם המשתמש, ואכיפת ההרשאות היא **בקוד** (`assistantAction`), לא בפרומפט.

## שלב 1 — הרשאות + טיוטות (בצד־לקוח, בלי חיבור אמיתי)
*היום־יומיים הראשונים. עובד על הפרוטוטייפ הקיים, מוכיח את חוויית האישור לפני שנוגעים ב־API.*

- [ ] סכמת כרטיס: הוספת `origin` ו־`draft` (כבר בסכמת ה־SQL; להוסיף גם למודל ה־JS).
- [ ] `profile.assistant` — מטריצת הרשאות (cards/calendar: suggest|draft|act · outbound: suggest קבוע).
- [ ] מסך הגדרות עוזר: שלושה מתגים 🔵🟡🟢 פר־סוג־פעולה + הסבר.
- [ ] **מצב "טיוטת העוזר"** לכרטיס — נשען על השפה הענברית הקיימת (`demo`), עם פס "אשר / דחה" (נשען על `adk-req` שכבר קיים). טיוטה שלא אושרה 7 ימים מתפוגגת.
- [ ] מילוי ידני של כמה כרטיסי־עוזר לדוגמה כדי להרגיש את הזרימה.
- [ ] `assistantAction(action)` — פונקציה אחת שכל פעולה עוברת דרכה; בודקת מטריצה → יוצר ישר / כ־draft / רק מציע.

**תוצר:** העוזר "מציע כרטיסים שאתה מאשר" — הליבה של החזון, עדיין מקומי.

## שלב 3 — העוזר החי (Claude API)
- [ ] Edge Function `/chat`: מקבל הודעה + תקציר מצב הלוח, מריץ את Claude עם **tools** (`search_email`, `list_events`, `create_card`, `move_card`, `draft_event`), מחזיר טקסט + רשימת פעולות.
- [ ] כל פעולה חוזרת דרך `assistantAction` → נכתבת ל־`assistant_action` → מיושמת לפי המטריצה.
- [ ] החלפת `answer()` הנוכחית (ה־if-ים) בקריאת Promise ל־`/chat`. אינדיקטור ההקלדה כבר קיים.
- [ ] "כרטיס פעולה" בתוך השיחה (העוזר יצר/מציע X, עם אשר/בטל) — נשען על `adk-req`.
- [ ] שיחה מאוחדת: `assistant_thread` + `assistant_message` (זיכרון מתמשך, בסיס ל"אחד בכל הדלתות").
- [ ] **חוקי הקול** ב־system prompt (סעיף 8 במסמך) + lint ביטויים אסורים (עדיין/שוב/מצטער/אתה צריך) לפני הצגה.

**תוצר:** שיחה חופשית אמיתית + יצירת כרטיסים מהשיחה. עדיין בלי מייל/יומן.

## שלב 4 — מקורות: יומן + מייל (OAuth + סריקת בוקר)
- [ ] Google OAuth (Gmail read, Calendar read) דרך Edge Function `/oauth-callback`; טוקנים ב־Supabase Vault.
- [ ] הצינור המלא מהמסמך: **איסוף → מיון → אימות → הגשה** (עם "בדיקה לפני יצירה" ומנוע כפילויות דרך `origin.ref`).

- [ ] "בדיקת רופא → משימה" ושאר הזרימות מהחזון.

**תוצר:** העוזר באמת "מסדר את המציאות" — מהמייל והיומן, בכבוד לחוקי הקול.

## שלושה כללי ברזל (בכל שלב)
1. **אכיפת הרשאות בקוד** (`assistantAction`), לעולם לא בפרומפט בלבד.
2. **תוכן שנאסף (מייל/יומן/שם קובץ) = דאטה לסיכום, לעולם לא הוראה לביצוע.**
3. **פעולה בלתי־הפיכה או שאחרים רואים — לעולם לא אוטומטית**, בשום רמת הרשאה.
